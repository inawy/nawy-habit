# خطة بناء Nawy Habit — مرحلة بمرحلة

كل مرحلة بتخلص وهي شغالة ومختبرة قبل ما نبدأ اللي بعدها، عشان الكود ما يتكسرش.

## المرحلة 0 — الأساس والجودة
- تنظيم المجلدات: `features/habits`, `lib/db`, `lib/date`, `components/ui`.
- ESLint بقواعد صارمة (TypeScript + React Hooks + منع الاستيراد غير المستخدم) + Prettier.
- TypeScript strict.
- Vitest + Testing Library + fake-indexeddb لاختبار قاعدة البيانات.
- سكربتات: `lint`, `typecheck`, `test`, `check` (الكل مع بعض).
- GitHub Actions: يشغّل `check` على كل push و pull request.
- نظام التصميم: ألوان وخطوط Nawy كمتغيرات، دعم الوضع الليلي، دعم العربي (RTL).

## المرحلة 1 — طبقة البيانات
- قاعدة Dexie بإصدار 1: جداول `habits` و `logs` (مفتاح اليوم YYYY-MM-DD).
- مخططات Zod لكل كيان.
- مستودع (repository) واحد للقراءة والكتابة، والواجهة ما تكلمش Dexie مباشرة.
- دوال التاريخ والسلاسل (streaks) كدوال صافية مع اختبارات وحدات شاملة (تغيير المنطقة الزمنية، الأيام الفايتة، العادات الأسبوعية).

## المرحلة 2 — الوظائف الأساسية
- إضافة / تعديل / أرشفة عادة.
- شاشة "اليوم": تسجيل بضغطة واحدة، والتراجع عنها.
- عرض السلسلة الحالية وأفضل سلسلة، من غير ما نعاقب المستخدم على الأيام الفايتة.
- اختبارات مكوّنات للتدفقات دي.

## المرحلة 3 — التقدم والتفاصيل
- صفحة لكل عادة: تقويم شهري ونسبة الالتزام.
- رسومات بسيطة (بدون مكتبة تقيلة إلا لو احتجنا).

## المرحلة 4 — ملكية البيانات
- تصدير واستيراد JSON (بإصدار للمخطط + تحقق Zod).
- طلب تخزين دائم من المتصفح (`navigator.storage.persist`).
- اختبار ترحيل البيانات بين إصدارات قاعدة البيانات.

## المرحلة 5 — PWA والعمل بدون إنترنت
- manifest وأيقونات.
- vite-plugin-pwa بـ generateSW، بيتسجل في النسخة المنشورة بس، مع إشعار "فيه تحديث".

## المرحلة 6 — الجاهزية للإنتاج
- حدود للأخطاء (error boundaries) وصفحة 404.
- مراجعة إمكانية الوصول (لوحة المفاتيح، التباين، aria).
- مراجعة الأداء وحجم الملفات.
- بيانات الصفحات (title / description) والنشر.

## التفاصيل التقنية
- كل تغيير في المخطط = `db.version(n+1).upgrade()` + اختبار ترحيل.
- اختبارات E2E بـ Playwright للتدفق الأساسي (المرحلة 6).
- القواعد دي تتسجل في AGENTS.md أول ما تتنفذ.
